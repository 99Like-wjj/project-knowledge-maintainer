# 数据约定讨论稿

**状态：待设计，非正式 schema，未实现解析或校验。** 本文仅列出创建维护端与使用方需要共同确定的语义，不锁定文件格式、字段名、枚举或版本号。

| 需要共同确定的事项 | 目的 |
| --- | --- |
| 项目身份、环境与适用范围 | 防止跨项目、跨环境误用 |
| 知识条目的稳定标识与引用方式 | 支持准确定位及更新后的引用检查 |
| 功能、角色、对象、流程与经验的关联 | 保留对使用方有用的上下文 |
| 来源与证据、知识可信状态 | 区分已确认规则、实际观察和待确认信息 |
| 更新信息与变更依据 | 支持增量维护和追溯 |
| 知识内容修订与规范版本的区别 | 避免把内容变动误判为协议变化 |
| 缺失、过时、冲突及兼容性问题的呈现 | 使用方能够发现问题，而不是猜测 |

设计时优先选满足目标的最小方案。项目知识产物是独立资产，存放于本仓库之外；Ego Lite 等使用方直接读取产物，不依赖调用本维护 Skill。

正式确定数据约定后，应由双方使用同一组合成资料验证创建、读取、更新、失效引用及不兼容情况。当前未提供正式样例或兼容承诺。
