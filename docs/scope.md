# 范围与开发交接

本文描述后续设计目标，不代表功能已经实现。当前只完成仓库骨架。

## 本项目负责什么

- 从授权资料创建某个项目的第一版知识库，允许资料不完整，明确覆盖范围和重要缺口。
- 整理功能地图、角色权限、业务流程、功能依赖、业务对象和数据关系，以及项目特有经验；接口知识可选，不是创建前提。
- 保留重要知识的来源和适用范围，区分规则、观察与待确认信息。
- 根据新资料定位受影响知识，增量更新，记录变更依据，检查关联引用、冲突和失效内容。
- 通过明确项目身份及范围避免跨项目、跨环境混用。

维护时可以读取和检查既有知识，但不因此承担测试运行时的查询服务。

## 本项目不负责什么

- Ego Lite 的通用测试经验优化、测试执行和运行时查询实现。
- 无人审核的自动学习，或把系统现状自动升级为正确业务规则。
- 自动扫描全部业务系统、复制全部原始资料、建立完整企业知识平台。
- 默认引入数据库、向量库、服务端或管理后台。

## 下一阶段需要决定

1. 最小存储形式、产物目录以及仓库外位置的指定方式。
2. 与使用方共享的[数据约定](data-contract-draft.md)，包括兼容性和错误呈现。
3. 来源、冲突及待确认信息由谁审核，确认后如何进入正式知识。
4. Skill 的完整工作流程、安装与分发方式。
5. 完全合成的跨项目样例与联通验收方案。

## 后续验收方向（当前均未执行）

- 从合成资料生成可追溯、可指出缺口的初版知识库。
- 切换另一合成项目时不串用身份、规则或关系。
- 新资料能触发有依据的增量更新，关联引用同步检查。
- 与使用方共同验证产物可直接读取、查询，更新后仍可正确使用。
- 缺条目、失效引用、冲突、过时及不兼容情况能明确呈现，不静默猜测。
- 规则、观察和待确认信息始终可区分；知识读取不扩大操作授权。
- 所有仓库内容与未来发布内容均不包含真实项目资料和凭据。

工程检查、合成示例验证与真实项目验证应分别记录；真实项目验证需要单独授权，其资料与证据不得进入本仓库。
