# 项目知识库初始化与首次建库设计

日期：2026-11-02。状态：**设计已确认，进入本地开发自测**。本文属于知识维护项目，细化[维护方案](v0.1.9-requirements-and-design.md)的创建能力；数据含义以[共享约定](data-contract-draft.md)为准。实际完成与检查范围见[开发自测](development-validation.md)。

## 1. 三种使用意图

| 用户意图 | 需要完成的事 | 完成边界 |
| --- | --- | --- |
| “先给这个项目建一个空知识库” | 初始化项目/知识身份和最小文件 | 空库有效，不表示已有业务知识 |
| “根据这些资料，为这个项目建立知识库” | 必要时初始化，再整理首版通用知识 | 可以一次完成，不让用户先手建目录或填 JSON |
| “往已有知识库补充资料” | 识别已有身份和内容，进入增量维护 | 不重新初始化、不重分配 ID、不清空旧知识 |

本库整理的是**项目内通用、可跨功能复用的规则与准备知识**，例如共同的角色/数据范围、环境约定、通用前提和项目经验。跨项目的一般测试方法仍属于 Ego 通用经验。功能只保留帮助定位的简要索引；逐功能字段校验、页面细节、特殊分支和完整用例不入库。

## 2. 初始化输入

| 信息 | 如何取得 | 缺失时处理 |
| --- | --- | --- |
| 项目名称与身份 | 使用当前任务已给信息；已有 projectId 则沿用 | 逻辑项目不清时先澄清，不凭目录名猜测 |
| 知识保存目录 | 用户指定或在当前任务中明确认可的仓库外路径 | 可提出具体路径，获确认前不写真实知识；已明确的位置不重复询问 |
| 操作意图 | 只初始化，或初始化并整理给定资料 | 可从任务自然语言判断，不强迫用户选择命令模式 |
| 适用环境/版本 | 仅记录已知范围 | 允许暂缺，不能自动填成全部环境适用 |
| 原始资料 | 仅首次建库时使用授权提供的资料 | 没资料仍可初始化；不自动扫描磁盘、网站或公司平台 |
| 版本管理意图 | 沿用明确的业务知识 Git 位置及授权 | 不提供 Git 也能创建文件；初始化知识不默认执行 git init、提交或远端配置 |

新项目没有现成 projectId 时可生成稳定 ID，并说明这是本次创建的身份；knowledgeId 标识这套知识资产。名称相同不能证明应复用另一个库，也不通过扫描其他项目来自动绑定。团队复制已有知识时保留原身份，不因换电脑重新生成。

## 3. 最小初始化产物

```text
<明确指定的独立知识目录>/
  knowledge.json
  topics/                       初始无条目
  sources/                      初始无来源
```

knowledge.json 只包含规范版本、knowledgeId、projectId、显示名称、实际创建时间及已知 scopes。创建时间使用带时区的真实操作时间，不充当规则生效时间。topics/sources 可在第一次写入内容时才建立；读取端允许空库阶段目录缺省，不要求 .gitkeep、空业务文件或模板规则。

允许 scopes 为空：表示适用范围尚未登记，不表示任意环境都适用。空库能被维护端和 Ego 识别为“身份有效、无已收录知识”；不能因无主题就判成损坏，也不能把结构有效报成业务知识已就绪。

不生成虚构角色、功能、规则或来源，不把合成示例灌进真实库。初始化回执留在返回结果或独立私有工作区，版本化知识目录不增加运行日志、整库修订目录或常驻服务。

## 4. 已有目录与重复调用

| 目标现状 | 初始化行为 |
| --- | --- |
| 路径不存在 | 在明确的目标位置创建最小知识库 |
| 已有空目录 | 检查后新增最小文件，不把“已有目录”误报为已建库 |
| 已有有效同项目知识库 | 返回已有身份、实际位置和内容概况；不改文件、ID、创建时间或历史 |
| 用户还提供了新资料，目标已有内容 | 说明转入增量维护，不以“首次建库”覆盖 |
| 已有知识库但项目身份不符 | 报告不匹配，保留原文件；不能因显示名称相近自动合并 |
| 有 knowledge.json，但格式损坏或规范不支持 | 报告检查问题，不重新生成文件掩盖异常；修复/迁移属于另外的明确任务 |
| 仅有 README、.git 等业务仓库骨架 | 当前任务已明确该业务知识位置且无文件冲突时可新增；保留现有内容，不把普通代码仓库自动当知识库 |
| 有来源不明的非空内容、路径实际是文件或冲突目标 | 指出具体冲突；改用明确的新目录或先确认用途，不无条件覆盖 |

写入前检查实际解析后的路径与文件冲突。真实知识不能落入两个通用 Skill 的源码或安装目录；AI 核对已知项目位置，工具拒绝自身源码/安装目录及显式保护路径。符号链接或 junction 不能绕过这些边界。

## 5. 安全写入与中断恢复

初始化只需要可靠创建一个身份文件，不建立持久化创建状态机。先在本次拥有的暂存文件中写入、校验并读回，再以拒绝覆盖的方式保存 knowledge.json；同时创建者已占用目标时，读回实际库并报告冲突或已有库，不产生第二套身份。

knowledge.json 已保存但回执丢失时，重试读取同一文件并返回已有身份，不再生成新 ID。暂存失败、无权限、磁盘写入异常或文件被并发改动时如实报告实际留下的内容，不能声称初始化成功。

只可核对并处理本次确实拥有的暂存文件或空目录；不删除不明文件、不重置 Git，也不靠“重新初始化”修复半完成的首次建库。若已有合法身份而资料整理未完成，应保留身份并从已有内容续接。

首次建库的多文件保存复用维护方案中的指纹检查、暂存校验与读回；部分完成时区分身份初始化和知识内容状态，不能把半成品标成完整首版。

## 6. 首次建库的内容选择

AI 从已提供资料中筛选对以后测试有复用价值的项目通用信息，保留依据、范围和必要的关系；不默认逐功能展开，也不将整份需求逐条转换成知识条目。推荐按角色与权限、公共数据关系、环境与准备约定、共用业务约束等少量主题组织，实际选取仍由 AI 判断，不硬定条目数或复用次数。

| 可沉淀 | 留在原资料或本次用例中 |
| --- | --- |
| 明确跨功能适用的角色权限和数据可见范围 | 某一个表单的字段必填、长度、精度及全部校验提示 |
| 通用对象归属、共用状态含义或数据关联约束 | 每个功能的完整状态分支和全部输入输出规格 |
| 项目共用前提、数据准备及反复需要的操作经验 | 逐页操作脚本、选择器、坐标和完整测试用例 |
| 功能用途/入口的短索引与原文位置 | 将每个功能的需求正文重复收录一遍 |

通用规则有功能特例时，保留简短适用边界和特例原文指引，不能删掉边界后推广为全项目规则；完整细则仍留原文，测试相应功能时按需读取。来源元信息可登记，但不把原文全文作为知识正文。

无法确认的通用信息保留 pending 或相关问题，不因想做“首版”而补全。资料只含单功能细则、没有可确认通用知识时，允许交付空库及清楚的说明，不凭空生成公共规则。刻意不收录的功能细则属于范围外，不逐项制造缺口清单；真正影响公共规则或本次判断的缺口才需要说明。

## 7. 一次请求的衔接与 Git

“根据资料建立知识库”可在同一请求内连续初始化和首次整理，不要求用户在两步之间再次批准已授权的本地操作。若初始化成功但资料无法读取、通用规则存在冲突或内容只完成一部分，应分别说明，不把整件事简单报成成功或失败。

已有业务 Git 仓库可承载知识文件，但不改其远端、分支或已有未提交内容。用户明确要求启用本地 Git 或保存首个提交时，可在授权内衔接并按文件审查；提交不能包含意外原始资料、凭据或其他产物。不自动上传 Coding，也不为知识初始化制造团队“正式发布版本”。

没有 Git 不影响空库和首版文件生成；回执说明尚无 Git 历史。后续覆盖式维护前须按维护方案保留前版，不因此引入第二套版本控制工具。

## 8. 完成回执与 Ego 交接

回执以简短可读结果为主，必要时提供机器可读信息：实际路径、knowledge/project 身份及规范、创建或复用的文件、空库/已有内容概况、未知范围、通用主题和条目数量、来源与未解问题、内容指纹，以及实际可得的 Git 状态。未执行的 Git 动作不填完成。

只初始化时说明“已初始化，尚无知识内容”；有知识时说明收录的是哪些通用主题，功能细则保留在何处。不给空库添加“业务已验证”标签，不为没有初始化的目录伪造回执。

Ego 取得明确知识目录与项目身份后，自行读取共享格式。默认只查与任务相关的通用规则及必要索引，具体功能规则到原始需求按需查阅，不为缺少功能细则要求重新扩充整座知识库。

## 9. 验收设计

| 场景 | 应核对的结果 |
| --- | --- |
| 只有项目与目标位置、无资料/环境 | 可以生成有效空库；范围未知可见，没有虚构业务知识 |
| 新目录与已有空目录 | 能完成最小创建；必要读回与实际文件对应 |
| 对同一空库重复初始化 | ID、创建时间和现有字节不变，返回已存在 |
| 已有内容、另一个项目、坏格式或非空冲突目录 | 分别复用/维护或报告问题，不覆盖原知识 |
| 两次初始化竞争、写入中断、回执丢失 | 不分配两套已生效身份，不将半完成结果报成功；可读回真实状态 |
| 空目录缺省或 Git 骨架位置 | 空库仍可识别；现有仓库内容不变，未授权 Git 动作不发生 |
| 少量公共规则混在大量功能细则中 | 只整理复用知识与必要索引；细则留原文，不逐项生成范围外缺口 |
| 公共规则带功能特例 | 适用边界保留，细则原文可定位，不错误推广 |
| 一次请求初始化并首次建库 | 无需用户手工搭骨架；部分结果和未完成原因明确 |
| Ego 读取空库或首版 | 分别识别无内容和相关通用主题；默认不加载整份功能需求 |

执行情况分别见开发自测记录。工程验证检查文件事务、身份及引用；AI 合成场景检查是否恰当筛选通用知识、保持轻量并按需使用。两者均不代表真实项目验收，也不凭条目少就声称执行更快。
